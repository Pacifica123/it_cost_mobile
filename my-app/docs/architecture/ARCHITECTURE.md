# Архитектура проекта

## Общая идея

Приложение построено как Expo/React Native проект с маршрутизацией Expo Router. Логика разделена по функциональным модулям.

## Главные слои

```text
app/        экраны и маршруты
features/   бизнес-функции и UI отдельных доменов
shared/     общие компоненты, тема, форматтеры
store/      состояние приложения и сохранение
scripts/    генераторы и проверки
tests/      логические тесты
docs/       документация
```

## Пользовательская структура

Приложение должно вести пользователя по сценарию:

```text
Проект → Расчёты → Аналитика → Отчёт
```

Сервисные действия вынесены отдельно:

```text
Настройки → Диагностика → Обновления
```

## Данные

Основные данные проекта включают:

- паспорт проекта;
- CAPEX;
- OPEX;
- техническое оборудование;
- программное обеспечение;
- электроэнергию;
- настройки;
- историю;
- резервные копии;
- курсы валют;
- сохранённые проекты.

## Настройки

Настройки должны влиять на реальное поведение:

- тема меняет цвета экранов;
- размер интерфейса меняет плотность карточек;
- валюта меняет отображение сумм;
- курсы валют меняют пересчёт отображаемых сумм;
- горизонт расчёта влияет на TCO/NPV/графики;
- настройки отчёта влияют на выгрузку;
- CSV-настройки влияют на импорт.

## Тема

Тёмная тема должна использовать значения из общего слоя темы. Нельзя добавлять жёсткие `#fff`, `#000`, `#f8fafc` в компоненты, которые видит пользователь, если они не обёрнуты в тему.

## Навигация

Физически маршруты могут оставаться плоскими, но в UI они группируются:

- Проект;
- Расчёты;
- Аналитика;
- Отчёт;
- Сервис.

## Проверки

Ключевые проверки:

- `check-router`;
- `check-duplicates`;
- `check-functionality`;
- `check-menu-it`;
- логические тесты.

Эти проверки должны запускаться перед сборкой APK.
