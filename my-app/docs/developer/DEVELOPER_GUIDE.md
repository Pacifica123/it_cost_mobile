# Руководство разработчика

## Требования

- Node.js.
- npm.
- Expo CLI через `npx expo`.
- Для облачной сборки APK — EAS CLI.
- Для штатной работы EAS желательно установить Git.

## Установка

```bash
npm install
```

## Запуск

Обычный запуск:

```bash
npm run dev
```

Запуск с очисткой кэша Expo:

```bash
npm run fresh
```

Android:

```bash
npm run android
```

Web:

```bash
npm run web
```

## Главные команды

| Команда | Назначение |
|---|---|
| `npm run preflight` | Очистка старых вкладок, генерация маршрутов, проверки роутера и дублей |
| `npm run check` | Полная проверка перед сборкой |
| `npm run test:logic` | Логические тесты |
| `npm run gen:tabs` | Генерация вкладок |
| `npm run check:router` | Проверка маршрутов |
| `npm run check:duplicates` | Проверка дублей вкладок, маршрутов и стартовых данных |
| `npm run check:functionality` | Проверка экранов, заглушек и битых переходов |
| `npm run check:menu-it` | Проверка структуры Меню ИТ |

## Перед любым архивом/релизом

```bash
npm run check
```

Если нет `node_modules`:

```bash
npm install
npm run check
```

## Структура проекта

| Путь | Назначение |
|---|---|
| `app/` | Expo Router экраны |
| `features/` | Функциональные модули |
| `shared/` | Общие компоненты, тема, утилиты |
| `store/` | Состояние и локальное сохранение |
| `scripts/` | Проверки и генераторы |
| `tests/` | Логические тесты |
| `docs/` | Документация |

## Правила добавления нового экрана

1. Добавить экран в `app/it-cost`.
2. Добавить запись в реестр экранов.
3. Проверить, что у экрана есть `default export`.
4. Проверить, что маршрут отображается в нужном разделе, а не дублируется.
5. Запустить:

```bash
npm run gen:tabs
npm run check
```

## Правила UI

- Не добавлять новый верхнеуровневый раздел без необходимости.
- Сначала искать существующий раздел: Проект, Расчёты, Аналитика, Отчёт, Сервис.
- Не держать опасные действия на первом экране.
- В тёмной теме не использовать жёсткие светлые цвета.
- Цвета брать из общей темы.
- Большие тексты переносить в описания/подсказки, а не в заголовки.

## Правила данных

- При изменении структуры состояния повышать `schemaVersion`.
- Добавлять миграцию старого состояния.
- Не ломать чтение старых ключей `itcost_store_v*`.
- Для опасных операций использовать резервные копии.

## Что считается ошибкой перед релизом

- Есть дубли маршрутов.
- Экран есть в меню, но файла нет.
- Файл экрана есть, но нет регистрации.
- Есть `TODO`, `FIXME`, `не реализовано` в пользовательском пути.
- Кнопка ведёт на несуществующий маршрут.
- Тёмная тема показывает светлые карточки без причины.
- Демо загружается, но отчёт/сводка показывают нули.
