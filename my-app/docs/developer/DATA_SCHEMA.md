# Схема данных и миграции

## Версия данных

Состояние приложения хранится с `schemaVersion`. При изменении структуры данных нужно повышать версию и добавлять миграцию.

## Правила миграций

1. Не удалять чтение старых ключей без необходимости.
2. Новая версия должна уметь открыть старое сохранение.
3. Если поле добавлено — задавать безопасное значение по умолчанию.
4. Если поле переименовано — переносить значение.
5. После миграции сохранять данные в новом ключе.

## Что хранится

- паспорт проекта;
- CAPEX;
- OPEX;
- ТО;
- ПО;
- электроэнергия;
- настройки;
- курсы валют;
- история;
- резервные копии;
- сохранённые проекты;
- план внедрения;
- checklist.

## Опасные операции

Для таких действий желательно делать резервную копию:

- очистка проекта;
- импорт CSV;
- применение шаблона;
- массовое удаление;
- восстановление другой копии.

## Проверка после миграции

```bash
npm run check
```

Ручная проверка:

1. Запустить приложение на старых данных.
2. Убедиться, что данные открылись.
3. Изменить проект.
4. Перезапустить приложение.
5. Проверить, что состояние сохранилось.
