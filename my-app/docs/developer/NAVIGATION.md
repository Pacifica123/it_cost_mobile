# Навигация и маршруты

## Основной принцип

Не показывать пользователю все экраны одним длинным списком. Экраны группируются по задачам:

```text
Проект
Расчёты
Аналитика
Отчёт
Сервис
```

## Что считается верхним уровнем

Верхний уровень — это не технический маршрут, а понятная пользовательская зона:

- **Проект** — управление проектом.
- **Расчёты** — ввод исходных данных.
- **Аналитика** — анализ результата.
- **Отчёт** — проверка и выгрузка.
- **Сервис** — настройки и диагностика.

## Что нельзя выносить наверх

Не выносить отдельными большими пунктами:

- резервные копии;
- очистку;
- историю;
- диагностику;
- графики;
- демо;
- CSV-импорт.

Они должны находиться внутри соответствующих крупных разделов.

## Проверка меню

После изменения маршрутов:

```bash
npm run gen:tabs
npm run check:router
npm run check:duplicates
npm run check:functionality
npm run check:menu-it
```

Или одной командой:

```bash
npm run check
```

## Типовые ошибки

| Ошибка | Что делать |
|---|---|
| Экран есть, но не открывается | Проверить route в реестре |
| Экран виден дважды | Проверить группы и include/exclude |
| Вкладок стало больше двух | Проверить `app/it-cost/(tabs)` |
| Кнопка домой ведёт не туда | Проверить стартовый экран и redirect-логику |
